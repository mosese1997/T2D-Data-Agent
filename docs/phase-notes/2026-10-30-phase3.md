## 过程中发现并修复的问题（都有验收断言覆盖）

1. **指标卡绑定错值**：模型曾把多行分组 Source 绑到"总量"指标卡（会显示第一行而非总量）→ 查询 Agent 改为可产出 KPI+明细双 Source（purpose 标注），设计提示词硬约束"指标卡只能绑单行 KPI Source"。
2. **重复提议**：模型 propose 成功后又调一次且失败，runner 只看最后一次工具结果 → 改为以 DB 中本任务的 validated patch 行为准（`_validated_patch`），提示词明确"validated 后不要再提议"。
3. **MaaS 内容审查误杀**（"May contain sensitive information"，概率性，同文本时过时不过）→ LLM 客户端对软性 403 做 4 次退避重试（2/4/6/8s）；硬 403 不重试。
4. **SSE 闭包陷阱**：generate() 内对 cursor 赋值致 UnboundLocalError（流空响应）→ nonlocal 修复。
5. **JSON 列序列化**：psycopg 返回的 date/decimal 不能直接进 JSON 列 → runner 统一 `_jsonable()`。
6. **SQLite 写锁**：worker 长事务持锁阻塞 audit/trace 短事务 → 全部改短会话（每事件/每工具调用独立提交）。
7. dev_up.sh：修复 `&&` 链与 `&` 优先级导致 export 进了后台子 shell、worker 拿不到模型密钥的问题。
