## 彩排过程（真实复现部署文档的每一步）

1. 停开发栈释放端口 → `docker compose up -d --build`（4 镜像：api 211MB / worker 207MB / nginx 49.5MB / sandbox 363MB）。
2. 数据灌入 compose 业务库（psycopg COPY，30 万订单）。
3. 全新状态库：迁移 + 三种子（宿主机初始化 → docker cp 注入容器卷，即 deployment.md 记录的已知限制路径）。
4. 经 :8080 全链路验证：登录 → 预置看板 → 自然语言建板 → Apply。
5. answer 模式经 :8080 验证（问答直答）。
6. 还原开发栈（业务库卷数据无损：300,000 orders 复核）。

## 彩排抓出并修复的部署问题（这正是彩排的价值）

1. **镜像内 `-e` 可编辑安装失效**（路径指向构建阶段目录）→ 改常规安装。
2. **容器内配置目录解析越界**（parents[3] 在 /app 布局下不存在）→ 环境变量优先 + 逐级向上回退。
3. **worker 镜像缺 opensandbox 依赖** → 补进 pyproject。
4. **nginx 缓存上游容器 IP**（容器重建后 502）→ 重建后需 restart nginx（已写进 deployment.md 注意事项）。
5. **验收脚本 pipefail 误报**（curl|head 的 SIGPIPE 非零被 pipefail 放大）→ 先捕获后判断。
6. **compose 重建切换窗口**（healthz 打到旧容器）→ 稳定等待 + 重试。
7. **dev_up 沙箱进程未完全脱离管道**（`dev_up.sh | tail` 挂死）→ setsid + 全 fd 脱离。
