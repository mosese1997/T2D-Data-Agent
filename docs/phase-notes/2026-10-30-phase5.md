## 分析 Sub-agent + 沙箱（实测通过）

- **管线**：意图段判 mode=analysis → 查询段产出当期/上期双 Source（purpose 标注）→ 分析 Agent 调 run_analysis（沙箱贡献分解）→ 非因果中文结论 + analysis_id。
- **沙箱 profile**（boundaries.md 全项落实）：1vCPU/1GiB、**禁网显式 opt-in**（默认放通，适配层每次强制传 deny）、120s 命令超时、TTL 10 分钟兜底、finally destroy、零宿主挂载、无凭据注入。
- **实测结论质量**：贡献数字与独立核算一致（厄瓜多尔 44.31%/巴西 37.04%/巴拿马 10.34%）；明确声明"贡献分解不构成因果解释"；用户前提错误时用真实数据纠正（"GMV 实际是上升的"）。
- **贡献分解模板是确定性代码**——模型不能悄悄歪曲数学；custom 代码必须走结果契约（/tmp/t2d_result.json）。

## 评测体系（任务书 §18）

- **39 个固定用例**：27 自然语言（基础问数 10/澄清 4/权限 2/分析 2/口径 2/去重 1/汇率 1/空结果 1 + 行为 4）+ 12 脚本（超时/取消/沙箱失败/禁网/网关拒绝/幂等/租约回收等）。
- **判定器比较结果值**（与独立 reference SQL 对账，容差内命中），从不比较 SQL 字符串；行为用例断言澄清/诚实拒绝/非因果表述。
- 评测抓出的真问题（均已修）：
  1. 我自己的 reference SQL"上周"写错一周（判定器与 Agent 分毫不差地对上了正确值，反证 reference 错）。
  2. **fx 缺失日 Agent 返回 NULL 而非回退**——提示词写了 LATERAL 但模型没遵守 → 修法：建 `v_orders_fx` 视图把口径规则**结构化**（0 NULL/30 万单），语义版本升 2，提示词禁止手写 fx JOIN。修后 12.22 精确命中。
  3. 退款率/销量/年份等用例表述缺陷（口径不明/伪歧义/缺年份）→ 明确表述。
  4. cancel 测试时序（等 running 再取消）。
- 运行：`python evals/runner.py --case-set smoke|nl|scripted|full`，`--filter` 定向重跑；结果落 eval_runs 表 + evals/reports/。
